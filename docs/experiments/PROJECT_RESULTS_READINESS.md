## 3. 实验地图与可用结论

### 3.1 Baseline 50：生成完成率与预算问题

- 配置：跨GSM8K、MATH、AIME共50题，`math-solver-v1`、high、`max_tokens=4096`。
- 请求成功50/50，完整生成27/50，截断23/50。
- 27条完整回答全部答案正确；端到端可验证正确答案产出率为27/50，即54%。
- 23条截断消耗97,976 tokens，占本轮总tokens的72.1%。
- 结论：该实验主要证明4096预算不适合high生成，不能把27/27完成后正确率写成整体准确率。

用途：总报告中的“早期基线与问题发现”，不与后续stream/high/32000或low实验合并。

### 3.2 high/16000部分对照：提高预算的代价

- 对23条历史截断题计划重跑，实际保存16题。
- 12/16恢复为`stop`，4/16仍截断；总tokens为167,169，是同16题4096轮的约2.45倍。
- 结论：增加预算提高完成率但不能保证完成，且成本显著上升；由于只完成16/23，不能外推为完整对照。

用途：支持生成预算决策，不作为正式模型准确率结果。

### 3.3 Solver prompt v1/v2 25题配对

- 样本：MATH Level 1-5各5题，每题分别生成v1与v2，共50次Solver调用。
- 两版均25/25完整、25/25答案正确、25/25过程被Evaluator判为有效。
- v2步骤从155降至117，减少24.5%；结构复核从5降至0。
- Evaluator调用从180降至142，总tokens从320,085降至263,349，减少17.7%。
- Solver总tokens从125,879增至127,347，增加1.17%；v2不稳定降低Solver成本。
- 结论：v2更适合结构化过程评估并降低Evaluator成本，但正确样本不能验证首错定位或错误分类能力。

用途：总报告中的“Solver prompt设计与结构/成本对照”。

### 3.4 Level 4/5 high 20题与45题候选池

- high 20题均使用`math-solver-v2`、stream/high/32000，20/20完整、20/20答案正确。
- 共使用183,742 tokens，其中166,318为reasoning tokens。
- 与旧25题v2组成45题候选池；候选池用于来源选择，不是Evaluator准确率benchmark。

用途：说明高难度候选池来源，以及low 20题的同题high对照基线。

### 3.5 受控错误有效性验证

历史v1含自我揭示措辞，仅保留为行为探针；去提示化v1.1更接近自然错误表达；分类prompt v1.2在相同16例上重跑，并按新版分类边界复核人工标签。三轮结果必须分开报告，不能混成一次实验。

当前主要结论采用v1.2：

| 指标 | 结果 |
| --- | ---: |
| 过程错误检出 | 16/16 |
| 首错Step exact match | 16/16 |
| 错误类型 exact match | 14/16 |
| Local状态 | 15/15 |
| Local错误类型 | 13/15 |
| Local错误来源 | 15/15 |
| Global状态 | 16/16 |
| `process_complete` | 13/16 |
| `final_answer_supported` | 16/16 |
| 答案—过程关系 | 16/16 |
| `needs_review` | 1/16 |

三个正确答案但错误过程案例均被识别为`correct_answer_invalid_process`。仍保留两类分类失败：具体非法推导与计算错误边界、末端条件遗漏与答案提取/格式错误边界。唯一复核案例主要来自当前schema不能把`final_answer`表示为错误位置。

用途：总报告中的“过程评估器有效性验证”。这些是受控探针上的一致性指标，不能解释为自然错误总体准确率。

### 3.6 low Level 4/5 20题自然错误实验

- 落盘审计确认20条Solver请求和136次Evaluator调用全部为`reasoning_effort=low`。
- Solver 20/20完整、20/20答案正确；Evaluator预测19/20过程有效。
- 人工确认`math-test-precalculus-0488`存在Step 7符号错误，但最终答案`6/23`正确，形成自然`correct_answer_invalid_process`案例。
- 同题Solver总tokens从high的183,742降至low的60,706，减少67.0%；reasoning tokens减少73.8%。
- Level 4为10/10答案正确、10/10过程预测有效；Level 5为10/10答案正确、9/10过程预测有效。

用途：总报告中的“推理强度、成本与自然错误案例”。后续low自然45题全量单人复核已覆盖本组20题，19条valid均确认有效，唯一invalid确认属实。

### 3.7 45题、受控16例与low 20题的关系和当前覆盖

旧25题v2可以作为后续测评题目。它与新增Level 4/5共20题构成同一个45题自然解答池，层级分布为Level 1-5分别5、5、5、15、15。45条high解答均为Solver自然生成，全部完成且最终答案正确；人工错误注入是在其中16道不同源题上派生的独立受控版本，不会覆盖或改变45条自然解答。

| 数据部分 | Solver自然解答 | 答案验证 | 自然过程评估 | 人工过程真值 |
| --- | --- | --- | --- | --- |
| 旧25题v2 | high 25/25 | 25/25正确 | high 25/25 | 未系统标注 |
| 新增Level 4/5 20题 | high 20/20 | 20/20正确 | 未批量运行 | 未系统标注 |
| 同题low Level 4/5 20题 | low 20/20 | 20/20正确 | low 20/20 | 20/20已单人复核 |
| 从45题派生的受控16例 | 人工改写的独立版本 | 预期答案已核验 | high 16/16（v1.2） | 有冻结首错、类型和全局标签 |

因此，“high已有45道解题与评估”需要拆开表述：high Solver和答案验证覆盖45题，high自然过程评估目前只覆盖旧25题。受控16例虽然由45题中的源题派生，但不是45条high自然过程评估的一部分。

### 3.8 low自然45题与新版Evaluator推理强度对照

- 旧25题已补充low Solver与新版low Evaluator，和原low 20题合并为同题low 45；Level 1-5为5/5/5/15/15。
- low Solver 45/45完整、45/45答案正确，共113,594 total tokens；同题high为311,089，减少63.5%。
- low Evaluator共278次完整调用，预测44条过程有效、1条错误；45条可见过程经单人复核为44条有效、1条无效，与Evaluator逐条一致。答案层4条坐标元组格式提示也均人工确认正确。
- 同一受控16例在冻结新版prompt和可见解答后仅改变Evaluator推理强度：high/low错误检出为16/16与13/16，首错为16/16与14/16，类型均14/16，复核为1/16与3/16。

用途：Solver 45题是严格的同题强度与成本对照；受控16例是严格的新版Evaluator强度对照。旧25题high过程评估仍只作为旧版评估器的正确过程接受与结构成本证据。

## 4. 建议冻结的统一统计口径

所有指标必须先按实验配置和唯一`inference_id`去重；不同prompt、reasoning强度、token上限、重试策略和受控/自然输入分开统计。

| 指标 | 建议定义 | 说明 |
| --- | --- | --- |
| 请求成功率 | 成功API请求数 / 计划逻辑请求数 | 无模型响应的连接失败另报，不混入模型质量 |
| 生成完成率 | `finish_reason=stop`的目标数 / 目标样本数 | HTTP成功但`length`不算完整 |
| 完成后答案正确率 | 正确答案数 / 完整生成数 | 只回答完整样本上的答案质量 |
| 端到端答案产出率 | 完整且答案正确数 / 目标样本数 | 截断统一记为未验证，不当作模型错答 |
| Parser无警告率 | 无parser warning的完整生成数 / 完整生成数 | 结构化答案复核数另报 |
| 过程评估完整率 | 完成Local与Global并通过严格schema的目标数 / 过程评估目标数 | 失败重试需按inference取最终完整记录 |
| 过程预测分布 | `process_correct=true/false/null`数量 | 没有人工标签时只称预测分布，不称准确率 |
| 错误检出率 | 人工错误样本中预测为过程错误的数量 / 人工错误样本数 | 主要用于受控错误集 |
| 首错定位准确率 | 首错位置exact match / 有人工首错标签样本数 | `final_answer`应作为合法特殊位置 |
| 错误类型准确率 | 类型exact match / 有人工错误类型样本数 | 标签版本必须与prompt分类版本一致 |
| 复核率 | `needs_review=true` / 过程评估目标数 | 同时记录进入复核的原因 |
| 自然问题命中精度 | 被Evaluator判为有问题且人工确认真实问题 / 被判为有问题并人工复核数 | 当前low实验为1/1，但分母太小，不能外推 |
| 自然误报比例 | 被Evaluator判为有问题但人工确认无问题 / 被判为有问题并人工复核数 | 不等同于对所有正确过程的传统false-positive rate |
| 成本 | Solver与Evaluator分别报告calls、prompt/completion/reasoning/total tokens和延迟 | 失败尝试与有效调用分开 |

最终报告中不得使用一个“总体准确率”混合以上不同含义。特别需要区分：最终答案正确率、Evaluator过程预测比例、受控错误上的一致性准确率，以及自然样本人工复核结果。

## 8. low扩展到45题的分析价值与边界

### 8.1 已完成的最小扩展

该扩展已经完成：旧25题v2补充low Solver与low Process Evaluator后，已形成完整同题high/low 45题自然解答集合；Level 1-5分布为5/5/5/15/15。

该扩展能够带来三类直接增益：

1. Solver准确率与成本：在完全相同的45道题上比较high/low的完成率、答案正确率、tokens、步骤数和延迟，并按Level报告。
2. 能力边界探索：补齐low在Level 1-3的基线，并把Level 4/5自然样本从每层10题保留到每层15题；可以观察错误是否集中于更高难度或特定学科。
3. 自然过程样本：增加评估器可发现的自然错误和正确过程候选，为人工复核后的误报、漏报与答案—过程独立性分析提供更大的样本池。

但45题仍是探索性分层样本，不是总体benchmark：Level 1-3各只有5题，且temperature为0.9、每个配置仅单次生成，不能据此宣称稳定的模型能力临界点。若新增25题仍全部答对，结论应是“在当前45题单次样本中未观察到答案准确率下降”，而不是low与high能力相同。

### 8.2 误报率必须依赖人工真值

最终答案正确不等于过程正确。low自然45题已有完整单人标签：44条过程有效、1条过程无效，Evaluator逐条一致；自然问题命中精度为1/1、被标记样本中的误报为0/1，分母不足以外推。

要计算传统意义的过程误报率和漏报率，需要先对自然解答建立独立人工标签：

- 假阳性：人工判定过程有效，但Evaluator判为错误；
- 假阴性：人工判定过程有错，但Evaluator判为有效；
- 真阳性与真阴性也必须来自同一人工口径。

当前low 45已经可以报告这组样本上的真实过程正确率与Evaluator一致率。若后续扩大自然样本，仍必须同步建立人工标签，否则只能报告答案表现、成本和Evaluator预测分布。

### 8.3 分离Solver强度与Evaluator强度

同时把Solver和Evaluator从high改为low，会同时改变被评解答和评估判断，适合比较整条low/high流水线的总体成本与结果，但不能把差异单独归因于Solver或Evaluator。建议在报告中使用以下两条分析轴：

| 分析问题 | 应固定什么 | 改变什么 |
| --- | --- | --- |
| Solver推理强度影响 | 同题、prompt、生成参数与统一的答案/过程人工口径 | Solver high vs low |
| Evaluator推理强度影响 | 同一份冻结的可见解答及相同prompt/schema | Evaluator high vs low |

第一条可由low 45扩展直接支持。第二条不必立即把全部解答重复评估：可先在受控16例、自然错误和分层人工复核样本上做小规模冻结输入对照，再决定是否扩大。另需注意，旧25题high过程评估使用Local/Global v1，现有low 20使用Local v1.1与Global v1.2；两者除推理强度外还存在prompt版本差异，不能直接作为Evaluator强度对照。新增high 20题也尚无high自然过程评估。若报告需要“完整45题high/low Evaluator对照”，必须使用同一版评估prompt对冻结解答补齐对应条件，否则只能报告Solver 45题配对与不同阶段、不同覆盖范围下的过程结果。
