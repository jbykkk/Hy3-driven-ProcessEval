# Process Evaluator 有效性验证报告

## 1. 验证方案

| 验证集 | 数量 | 验证目标 |
| --- | ---: | --- |
| 受控错误验证集 | 16 | 错误检出、首错定位和错误类型分类 |
| 常规解答验证集 | 45 | 误报情况及过程判定可靠性 |

受控错误验证集包含16例预设错误位置和类型的解题过程，用于提供明确的人工参考标签；常规解答验证集包含45份未经错误注入的Solver输出，并通过逐题人工复核建立过程正确性参考标签。两个验证集承担不同验证目标，各项指标分别统计。

## 2. 错误检出、定位与分类验证

在同一16例受控错误验证集上，分别使用high和low `reasoning_effort`运行Process Evaluator。两组实验固定解题过程、Step划分、人工参考标签、评估prompt、输出格式及生成参数，仅改变Evaluator推理强度，因此结果可以直接比较。high配置作为本项目Evaluator有效性验证的主要结果，low配置用于观察降低推理强度后的评估表现和资源开销变化。

- 错误检出率统计Local或Global Evaluator是否给出明确的`invalid`或`insufficient`错误证据，不要求确定性聚合器最终必须输出`process_correct=false`；
- 首错定位准确率以人工标注的最早主要错误步骤为参考，采用Step级exact match计算。（即对于错误只发生在独立`Final Answer`、因而没有具体错误Step的样本，即使Evaluator同样输出空步骤，也按未准确定位计入）
- 错误类型准确率统计Evaluator输出类别与人工参考标签完全一致的比例。

| 指标 | high | low |
| --- | ---: | ---: |
| 错误检出率 | 16/16（100%） | 15/16（93.8%） |
| 首错定位准确率 | 15/16（93.8%） | 13/16（81.3%） |
| 错误类型准确率 | 14/16（87.5%） | 14/16（87.5%） |
| 整体过程判定一致率 | 16/16（100%） | 13/16（81.3%） |
| Reasoning tokens | 134,182 | 76,315 |
| Total tokens | 353,599 | 290,652 |

high配置在16例受控错误中全部正确检出过程问题；其中15例准确定位至人工标注的首个主要错误步骤，错误类型分类有14例与人工参考标签一致。未计为准确定位的一例是最终答案格式错误：其数学步骤均成立，错误发生在独立`Final Answer`，没有可对应的具体Step。两例分类差异属于相邻错误类别之间的混淆，不影响错误检出。

各指标按不同目标独立统计，关系如下：
- 错误检出只要求Evaluator发现明确的问题证据；
- 首错定位进一步要求错误步骤与人工标签一致；
- 错误分类进一步检查类别是否一致；
- 整体过程判定一致率则要求确定性聚合结论与人工结论一致。

low配置中有两例体现了这一区别：最大面积案例已经识别`Step 3`依据不足，但聚合结果因不确定性进入复核；复数分支案例已经识别分支遗漏，但把首错提前到`Step 4`且聚合结果进入复核。这两例均应计为检出错误证据，但不都满足严格定位或整体判定一致。唯一真正未检出错误的是错误质因数指数规则案例。另有一例错误只发生在独立`Final Answer`，原始记录中的空步骤虽与人工标签字段相等，严格定位指标仍按未准确定位计算。

与high相比，low配置的Reasoning tokens减少**43.1%**，Total tokens减少**17.8%**；错误检出率由100%降至93.8%，首错定位准确率由93.8%降至81.3%，整体过程判定一致率由100%降至81.3%。因此，本项目采用high配置作为Evaluator有效性验证的主要结果，low配置用于反映推理开销与评估表现之间的权衡。

## 3. 误报验证与人工复核

误报验证使用low Evaluator对45份常规解答验证集的评估结果。该验证集中的45份解答最终答案均正确。为建立完整的过程正确性参考标签，全部样本均经过逐题人工复核，并与Evaluator判定逐条比较。

| 核验指标 | 结果 |
| --- | ---: |
| 最终答案正确的常规解答 | 45 |
| Evaluator判定过程存在问题 | 1 |
| 人工复核确认存在过程问题 | 1/1 |
| 人工复核确认误报 | 0/1 |

| 人工参考标签 / Evaluator判断 | Evaluator判定过程正确 | Evaluator判定过程存在问题 |
| --- | ---: | ---: |
| 人工复核过程正确 | 44 | 0 |
| 人工复核过程存在错误 | 0 | 1 |

唯一被判定存在过程问题的样本为`math-test-precalculus-0488`。人工复核确认其Step 7存在代数变换符号不一致，且后续推导未给出有效修正；尽管最终答案正确，该可见过程本身存在实质性错误。因此，该判定不属于误报，Evaluator给出的首错位置也与人工复核一致。

完整逐题人工参考标签见 [`results/regular_solutions_review.json`](../results/regular_solutions_review.json)。

## 4. 验证结论

在16例受控错误验证集上，high Process Evaluator实现100%的错误检出率、93.8%的严格首错定位准确率和87.5%的错误类型准确率。low配置虽然降低了推理token开销，但错误检出和首错定位指标出现下降，因此high作为当前Evaluator的主要验证配置。

在45份常规解答验证集中，Evaluator判定的唯一过程问题经人工逐题复核确认属实，其余44份过程正确样本均未被错误判定，当前验证集未观察到误报。受限于验证集规模，上述结果用于说明本项目Process Evaluator在当前实验范围内具备过程错误识别、首错定位和过程有效性判定能力，不能推广到其余数据分布以及模型整体性能相关结论。
